# Reserve synthetic CDB business codes as an explicit allocator

The type-49 CETIP allocator returns `ORA-06502` as code text in the test environment, database changes are unavailable, and independent NLS changes did not resolve it. With the operator's explicit permission to use synthetic COD_IF, CDB may opt into a format-compatible base-36 code range above both `A0000` and the live Oracle maximum for its prefix; Oracle remains the default allocator and COD_OPERACAO remains official. The subsequently supplied package source confirms base 36 and requires freezing the month from `CETIP.GET_DATAHOJE` together with the operational argument's year, which may differ from using the operational date for both.

Synthetic CDB ranges are persisted in the existing reservation ledger history under its lease/ETag CAS before publishing each immutable reservation. All CDB scenarios share a prefix namespace, failed publication burns its range, and materialization reproduces the frozen mapping while checking live collisions; the full reservation history must therefore be retained. This coordinates pipeline runs using that ledger, not native CETIP writers: the high starting range is headroom, not an exclusive database namespace, and target drift after preflight can still cause a load failure.
